## [2026-02-11] 작업 로그는 이벤트 기반으로 실시간 작성해야 함

- **문제**: Phase 1~3 작업 로그가 전혀 없고, Phase 4 로그도 작업 완료 후 요약 형태로만 작성됨. 변경, 수정, 에러 발생 시점의 세부 컨텍스트가 유실됨.
- **원인**: 작업 로그를 "완료 후 정리" 방식으로 접근. 이벤트 발생 시점에 즉시 기록하는 프로세스가 부재.
- **해결 방향**:
  - 작업 로그를 **이벤트 로그** 방식으로 전환
  - 파일 생성/수정, 에러 발생, 설계 변경, 테스트 실패/수정 등 **각 이벤트 발생 시점에 즉시 기록**
  - 기존 `_template.md`의 시간별 블록 단위를 더 세분화하여 이벤트 단위로 작성
  - 예시: `21:15 | [ERROR] MockK - exchangeRateProvider.sourceName() 미설정` → 원인 → 해결
- **교훈**:
  - 사후 요약은 "무엇을 했는지"만 남기지만, 이벤트 로그는 "왜 그렇게 했는지"까지 보존한다
  - 다음 세션에서 컨텍스트 복원 시 이벤트 로그가 있으면 디버깅 히스토리와 의사결정 과정을 재현할 수 있다
  - **모든 Phase에서 작업 시작 시점부터 이벤트 로그를 작성할 것**
